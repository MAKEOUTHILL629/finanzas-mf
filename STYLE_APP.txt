# ==============================================================================
# SISTEMA DE DISEÑO FINANCIERO: "LIQUID TRUST" & "SWISS GLASS"
# Versión: 2.0 — Complemento Integral
# CONTEXTO: Single Page Application (SPA) Angular + CSS Nativo
# FUENTE: Guías de Estilo Visual Financiero Moderno (2025-2026)
# ==============================================================================

La propuesta establece una filosofía de diseño denominada "Liquid Trust" (o "Swiss Glass"),
la cual fusiona la precisión matemática del Estilo Suizo con una evolución sofisticada del
glassmorphism que utiliza capas de desenfoque, saturación y bordes especulares para crear
profundidad semántica y jerarquía en el eje Z. A nivel visual, se rechaza el diseño plano
absoluto y los negros puros (#000000), optando por un sistema cromático "Deep Ocean & Ceramic"
(grises azulados profundos y blancos hueso) que reduce la fatiga visual en pantallas OLED,
complementado por una tipografía funcional (Inter) configurada obligatoriamente con Tabular
Figures (tnum) para garantizar la alineación vertical perfecta de los datos financieros.
El objetivo es evocar un "lujo silencioso" similar al de Apple, donde la interfaz se siente
sólida como una bóveda en su estructura de navegación (textura "concreto") pero fluida como
el mercado en sus paneles de datos (vidrio).

En cuanto a la Experiencia de Usuario (UX) y arquitectura, el sistema se basa en un "Bento
Grid" adaptativo que trasciende el diseño responsivo tradicional: se comporta como una pila
vertical eficiente en móviles y se expande modularmente en monitores ultra-wide (21:9) para
aprovechar la visión periférica con paneles de utilidad sin estirar el contenido. La interacción
se rige por la "física intuitiva", implementando micro-interacciones táctiles (botones que se
hunden al clic), validación de formularios en tiempo real y patrones de rendimiento críticos
como el Virtual Scrolling para manejar tablas con miles de transacciones sin bloquear el DOM.
Finalmente, la confianza se diseña mediante funcionalidades éticas, como un "Modo Privacidad"
global que desenfoca saldos sensibles y animaciones funcionales que confirman operaciones para
liberar dopamina y reducir la ansiedad financiera del usuario.


# ==============================================================================
# 1. FILOSOFÍA Y PRINCIPIOS (DIRECTIVAS PARA IA Y DISEÑO)
# ==============================================================================
# El diseño NO es "Flat" ni "Minimalismo Vacío". Es una fusión de "Precisión Suiza"
# (Estructura) y "Cristal Líquido" (Materialidad).
#
# Citas textuales extraídas de los documentos fuente:
# "El efecto 'Liquid Glass' se compone técnicamente de cuatro capas superpuestas que
#  deben implementarse vía CSS avanzado." — Diseño Web Financiero Moderno y Minimalista.pdf
# "La arquitectura visual propuesta se rige por tres pilares rectores: Claridad sobre
#  Reducción, Materialidad Semántica y Fluidez Responsiva." — Guía de Estilo Visual
#  Financiero Moderno.pdf

PRINCIPIOS RECTORES:
1.  Claridad sobre Reducción:
    - No eliminar datos necesarios. Usar jerarquía tipográfica para manejar densidad.
    - Regla: Priorizar claridad sobre reducción; no ocultar datos críticos, organizarlos.
    - Acción: Definir tokens tipográficos (hero, h1, body, small, caption) y aplicar
      font-feature-settings: "tnum" on, "zero" on; en todos los contenedores numéricos.

2.  Materialidad Semántica (Eje Z):
    - Fondo (Canvas) = Estático.
    - Vidrio (Paneles) = Flotante. Lo que está "más cerca" del cristal es más interactivo.
    - Regla: Paneles multicapa con semántica Z (más cercano = más interactivo).
    - Acción: Implementar clase base .panel-glass / .surface-glass con
      backdrop-filter: blur(20–25px) saturate(180%), borde especular y sombra interna sutil;
      ajustar blur según contraste del fondo.

3.  Contraste Vidrio vs Concreto:
    - Vidrio para datos; textura mate (concreto) para estructura de navegación.
    - Sidebar/header usan textura/grain CSS y colores sólidos; tarjetas y modales usan
      .surface-glass.

4.  Fluidez Responsiva (Bento Grid):
    - Móvil: Stack Vertical.
    - Desktop: Grid de 3 columnas.
    - Ultra-Wide (21:9): NO ESTIRAR. Usar "Zonificación de Productividad"
      (Paneles periféricos auxiliares).

  REGLA ESTRICTA DE FORMATO MONETARIO:
  - Símbolo de moneda SIEMPRE a la izquierda, pegado al número: $1,234.56
  - Miles separados con coma: 1,234,567.89
  - Decimales con punto: .00
  - Saldos SIEMPRE con 2 decimales: $1,234.00 (no $1,234)
  - Negativos con paréntesis contables: ($1,234.56), NO con signo menos
  - Porcentajes: +2.45% / -1.23% — con signo explícito y 2 decimales
  - Moneda secundaria entre paréntesis: $1,234.56 (€1,150.20)
  - Abreviaciones de cifras grandes: $1.2M, $450K — Solo en cards y gráficos, NO en tablas

  NOTA PARA AGENTES IA: Nunca renderizar un valor monetario sin decimales.
  Nunca usar notación tipo "1234.5" sin separador de miles.
*/

  - Imágenes/Ilustraciones: Reducir brightness un 10% en dark mode.

  - Cada componente DEBE ser testeado visualmente en AMBOS temas.

# 11. RENDIMIENTO Y OPTIMIZACIÓN
# ==============================================================================

/*
  REGLAS DE RENDIMIENTO:

  11.1 BACKDROP-FILTER:
  - Es GPU-intensivo. Limitar a máximo 5-6 elementos simultáneos con blur activo.
  - En dispositivos de bajo rendimiento: Degradar a fondo semitransparente sin blur.
  - Medir FPS con DevTools Performance panel.
  - Usar will-change: backdrop-filter SOLO en elementos que animan.

  11.2 VIRTUAL SCROLLING:
  - Obligatorio para listas/tablas > 100 items.
  - Usar Angular CDK Virtual Scroll (cdk-virtual-scroll-viewport).
  - Altura de fila fija (no variable) para cálculo óptimo del viewport.
  - Prefetch: Cargar 20 items adicionales fuera del viewport.
  - Target: 60fps con 10,000+ filas.

  11.3 IMÁGENES:
  - Formato: WebP con fallback JPEG.
  - Lazy loading: loading="lazy" en todas las imágenes fuera del viewport.
  - Avatares: Máximo 48x48px @ 2x (96x96px real).
  - Logos de bancos/instituciones: SVG preferido, PNG máximo 64x64.

  11.4 CSS:
  - Evitar selectores anidados profundos (> 3 niveles).
  - Usar clases utilitarias para propiedades repetidas.
  - No usar !important excepto en overrides de accesibilidad.
  - Critical CSS inlined en el <head> para above-the-fold.

  11.5 KPIS DE RENDIMIENTO:
  - TTI (Time to Interactive) del dashboard: < 2 segundos.
  - LCP (Largest Contentful Paint): < 1.5 segundos.
  - FPS durante scroll con virtual scrolling: ≥ 60fps.
  - Bundle size del CSS del design system: < 50KB gzipped.
  - Error rate en formularios (tras validación real-time): < 1%.
*/

  - Stroke-width consistente: 1.5px para iconos de 20px, 2px para iconos ≥ 24px.
